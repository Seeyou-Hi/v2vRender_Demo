# 机械臂仿真前端

双 UR5 机械臂浏览器仿真，包含夹爪切换、桌面物体、求解器、可选物理引擎和录制导出功能。

## 本地运行

安装 Node.js 20 或更新版本，在本目录 `frontend/` 执行：

```sh
npm start
```

打开 http://127.0.0.1:5175/ 。完整前后端启动请见根目录 README。

前端依赖已包含在仓库中，无需执行 npm install，也无需编译。启动程序仅监听本机地址；关闭终端或按 Ctrl+C 停止服务。

如需指定其他端口：

```sh
npm start -- 5176
```

## 目录结构

```text
robotarm/
├── dist/              实际运行的前端源码与静态资源，需要提交到 Git
│   ├── index.html     页面入口
│   ├── app.js         应用入口及其他功能模块
│   ├── style.css      界面样式
│   ├── models/        机械臂、夹爪、物体和桌面资源
│   └── vendor/        本地第三方运行依赖
├── server.mjs         本地静态文件服务
├── package.json       项目信息和启动命令
├── .gitignore         本地文件与导出结果的忽略规则
└── .gitattributes     文本换行和二进制文件规则
```

本仓库沿用 `dist/` 名称以兼容现有入口及资源路径。它是直接编辑的前端源目录，不是可删除、可重新生成的构建产物。修改页面、脚本和模型时直接编辑对应文件。

## Git 管理约定

- 提交 `dist/` 中的源码、运行依赖、模型、纹理及第三方授权说明，以及根目录的项目配置和启动文件。
- `recordings/`、`exports/`、`artifacts/`、`tmp/` 是本地输出目录，不提交录制视频、导出数组或临时产物。
- 不提交 `node_modules/`、缓存、日志和 `.env` 等个人配置或凭据。
- 第三方模型和依赖的来源、许可见各自目录的 README、LICENSE、UPSTREAM-LICENSE 和 SOURCE 文件，分发时保留这些文件。

## 后端写实渲染

在场景上方勾选“录制完成后自动写实渲染”，默认切换到当前网页视角、640×384、5 fps，并开启深度录制。可选择“深度控制”或“RGB 转 Canny”、标准或块编译模式，并填写场景描述。只支持单视角；深度控制需要勾选深度录制。录制设置在开始时保存，取消或部分生成的视频不会自动提交。

点击“录制视频”后操作机械臂，再点击“停止并生成”；也可使用自动演示中的“从头执行并录制”。本地视频生成完成后会自动上传，显示任务进度、已生成分块、完整视频预览和下载。首次分块需要点击播放；后续分块按顺序播放，可能因生成速度不足而等待。提交失败可“重新提交”；该按钮会创建新任务。刷新页面不会自动恢复任务进度。

前端服务器把 `/api/render/` 转发至 `http://127.0.0.1:8001`，无需浏览器跨域配置。后端在其他地址时，启动前设置：

```sh
KREA_BACKEND_URL=http://127.0.0.1:8001 node server.mjs
```

需通过 Node 服务打开网页；直接部署 `dist/` 时也需要为 `/api/render/` 配置等价的反向代理。“检查连接”只验证 HTTP 服务在线，不代表模型可以推理。自动录制模式上传完整视频后逐块返回；也可使用下面的流式模式。

点击“开始流式渲染”可边操作边传帧，无需先录完整段视频。使用所选单视角与深度/Canny 控制方式，前端采样固定 640×384、5 FPS；首批 9 帧，之后每批 12 帧，分别对应约 1.8 秒与 2.4 秒。后端同一会话复用模型和缓存，生成块可在输入结束前播放。点击“停止流式输入”后送完尾帧并生成完整视频；非循环自动演示结束时也会停止输入。

当前后端的流式时间轴仍固定为 16 FPS，尚需增加输入帧率声明与输出编码适配。前端会拒绝向未声明支持 5 FPS 的后端创建流式会话，避免把 5 FPS 帧流按 16 FPS 播放。整段 MP4 上传仍可根据视频帧率重采样。

后端队列满时，浏览器保留待发帧并暂停仿真，显示等待状态；慢 GPU 不会导致已采集帧被静默丢弃。模型加载、热身、采集和播放存在延迟，不保证实时或无缝播放。最多 4800 帧；不要在采集中刷新网页。新接口需要重启前后端服务。

后端的环境、模型路径和 GPU 数量按 v2vRender_Demo/krea/README.md 配置。本次只修改前端，不代表已完成真实 GPU 推理验证。

`npm run test:backend` 单独检查代理、上传、任务状态、分块和失败重试，使用模拟后端，不加载模型。没有 npm 时可运行 `node --test tests/backend-proxy.test.mjs tests/backend-render.test.mjs tests/stream-sender.test.mjs`。现有抓取测试使用 `Array.prototype.toReversed()`，需 Node.js 20 或更新版本。

## 静态发布

`dist/` 可作为静态网站根目录部署。当前仓库提供前端和本地服务，没有包含原项目的云端发布凭据或发布流程。模型与脚本应保持原有相对路径。

## 抓取规则

物品进入两指有效夹持区且未超出最大开口时，即可辅助抓取，无需横向对中。闭合从当前开口连续开始，近侧夹指接触后沿闭合方向把偏心物品逐步推向两指中央，物体朝向保持不变。每个小步检查夹爪主体、桌面与其他物体的碰撞；受阻时恢复最后安全位置并停止闭合，可松开夹爪调整。物理开关两种模式都支持该辅助过程；这不是基于摩擦和接触力的真实力闭合。

执行 npm test 可验证共享碰撞表面、左右偏移抓取、开口边界、朝向保持和无吸附跳变，以及连续推动居中、物理模式一致性和受阻回退。

验证补充：代理及前端状态/发送队列共 10 项测试通过；真实浏览器通过模拟后端发送 85 帧，顺序块为首块 9 帧、后续 12 帧、尾块 4 帧，RGB24 字节数与 input_fps=5 校验通过。旧 16 FPS 后端被拒绝创建会话。取消输入会释放占用并忽略旧轮询。此验证不包含实际 GPU 生成，公开静态网站仍需部署 /api/render/ 到真实后端的转发。

当前页面只显示渲染结果与操控仿真。RGB/depth 调试栏已移除，不保留 48 帧对照缓存。输入支持 gzip 无损压缩，Node 代理保留 Content-Encoding；输出最多六帧并发下载，按序以 5 FPS 播放。完整服务默认使用根目录 `start.sh` 启动。
