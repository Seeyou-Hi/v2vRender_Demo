# 单卡编译优化验证（2026-10-16）

C3 Slurm 作业 13974，同一张 A800-SXM4-80GB 顺序运行 eager/fused/blocks；CPU 对比作业 13975。环境与 krea/README.md 一致。输入为视频1前10秒、160帧、16 FPS、640×384，Depth＋相同参考图/提示词、seed 43、四步、TAE。每个变体完整160帧热身；热身后同时重置 VACE 编码器与主缓存。

| 实现 | 稳态生成 FPS | 160帧计算秒数 | 交付 FPS |
|---|---:|---:|---:|
| 原单卡 eager | 3.4717 | 47.5295 | 3.3663 |
| 336 子模块编译（单卡 bf16） | 3.7273 | 44.2459 | 3.6162 |
| 再编译48块（单卡 bf16_blocks） | 3.9283 | 42.0351 | 3.8063 |

稳态 FPS 按首块之后的原生生成帧计；交付 FPS 按实际160帧计。耗时不含加载、编译热身、编码。每块先9帧再12帧，末块裁去补齐帧。峰值 allocated 显存约49.52 GiB，不等同于整卡占用。

原单卡与保存基线逐像素一致。子模块/块编译相对基线 PSNR 分别43.13/43.55 dB；左右机械臂区域运动强度最佳相对滞后均为0帧，未发现新增运动活跃帧。抽帧对比中相机、物体布局和机械臂位置一致，存在小幅纹理差异。上述指标是输出间比较，不是动作物理精度保证；新单卡实现未做超过10秒的连续验证。所有输出 H.264/yuv420p/faststart，160帧且完整解码通过。

数值记录见 single_gpu_results_20261016.json。single_compile.py 的优化函数直接采用上述 GPU 实验的已验证代码；发布接入增加完整 KV cache 检查、单卡启动分支和 HTTP --gpus 1 支持。发布检查为 Python 语法、shell 语法及 CPU 接口/媒体测试，未重新执行统一 CLI 的 GPU 全流程。原多卡优化与 PAI 后端保留。
